Кнопка "Обновить из хранилища" немеделенный запуск команды, для проверки и отладки кода

Основной режим запуска - через регламентное задание. Обрабатываются все базы с галкой "Обновлять из хранилища"

Общий порядок действий при обновлени из хранилища:

Установка блокировки соединений

При этом запрещаются новые соединения с базой. Типовые БД с БСП  при этом начнут мягко выгонять  пользователей. Типовой алгоритм предпологает сначала уведомление, потом попытка завершить с сохранением открытых форм, затем принудительный выход. На ожидание работы типового механизма отводится 10 минут.

Блокировка устанавливается на 1 час. Если что то пошло не так, можно:

- зайти через час )

- зайти использовав код разблокировки, если задан в карточке

- в консоли кластера снять галочку блокировки с базы

Сброс зависших сеансов

Сбрасываются все сеансы текущей базы

Перезапуск рабочих процессов

Может производится мягкий перезапуск кластера. Рабочие процессы получают команду на остановку, поднимаются новые процессы, активные соединения переходят на новые, старые завершаются. Это штатный режим работы кластера. Для всех баз в кластере. После перезапуска настройки кластера возвращаются к исходным.

N.B.! следует понимать гарантированного пути перезапустить процессы одного кластера вендор не предоставляет. Правила игры периодически меняются, рекомендации и методы кластера перестают работать.

Альтернатива - назначенное задание Windows на перезапуск службы 1С. Это все кластеры на данном сервере.


Обновление из хранилища

Выполняется запуск конфигуратора в пакетном режиме. Конфигурация должна быть подключена к хранилищу. Под пользователем хранилища не должно быть других подключений. Из хранилища забирается последняя версия, обновляется конфигурация и база данных. Отчет об обновлении отправляется на почту всем адресатам из карточки ИБ.

Снятие блокировки

Последним снимается блокировка с базы. Если на предыдущих этапах ошибки - в обработке исключения все равно снятие болкировки

 

Дополнительно

Архивация базы не производится. Это джолжно делаться, например, средствами SQL сервера. Следите чтобы создание бакапов не пересекалось по времени с регламентом обновления. 

При ошибках настройки \ выполнения ошибки можно посмотреть:

- в почте, если настроеные параметры почтового сервера

- в журнале регистрации этой базы по событию "Ошибка обновления"

- в стандартном сообщении при использовании кнопки "Обновить из хранилища"

Стандартный ход обновления можно трассировать в журнале регистрации по событию "Обновление из хранилища"

Желтым фоном выделены пути к контексте сервера 1С, путь к хранилищу может быть unc //
